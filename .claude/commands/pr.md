Create a pull request for the current branch.

1. Run `git status` and `git log main..HEAD --oneline` to understand what's changed.
2. Run `pnpm --filter @dealwire/api lint && pnpm --filter @dealwire/api exec tsc --noEmit` — if either fails, fix the issues before proceeding.
3. **Find related issue:** Check the branch name for an issue number (e.g. `feat/197-...` → #197). If none in branch name, search with `gh issue list --repo dealwire-ai/dealwire --state open` for a matching issue.
4. Write a PR title in conventional commits format: `type: short description` (under 70 chars, imperative mood, no period).
5. Write a PR description with:
   - What changed and why (not a list of file names)
   - Any migration notes if the Prisma schema was modified
   - Any env var changes needed
   - `Closes #<number>` at the bottom if a related issue was found (this links the PR in the issue's Development sidebar)
6. Run `gh pr create --title "..." --body "..."` to open the PR.

Rules:

- NEVER add Co-Authored-By, Generated by, or any AI attribution anywhere.
- PR title and description must read like they were written by a human developer.
- If there are uncommitted changes, commit them first with a logical commit message.
- Always link the PR to a GitHub issue when one exists — use `Closes #N` in the body so it appears in the issue's Development tab and auto-closes on merge.
